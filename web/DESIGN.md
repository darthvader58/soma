# SOMA research dashboard

Direction: a professional planetary research workspace. ENERGY 2 / RHYTHM 2 / MOTION 2. Fixed dark slate surfaces surround a dark, neutral Moon scene. The user explicitly requested dark only, overriding the Anti-slop theme-toggle requirement. There is no appearance control or stored theme preference.

The researcher's task is to select sourced locations, define an interval, run Python geometry, inspect the exact sample and preserve a reproducible result. The site catalog, Moon scene, numerical inspector and shared UTC dock each own one part of that task. No feature-card grid, invented KPI, decorative activity indicator or marketing hero belongs here.

- Dark working panels separate editable inputs and readable numerical evidence from the spatial scene.
- Slate typography and restrained amber selection make the current study and primary action easy to identify without making every label compete.
- The existing system reading face keeps controls familiar; tabular numerals align UTC epochs, angles, ranges and source hashes.
- A stronger title, distinct section headings, compact catalog rows and more generous field spacing establish hierarchy at research-tool density.
- The center scene gets the largest continuous area. Camera controls stay on the scene; scientific status and result quality stay outside it.
- The UTC dock groups playback, exact time, plot, comparison and reproducibility information. It remains usable when tiles fail.
- The single dark palette covers text, controls, chart strokes and keyboard focus. The full name, Selenographic Observation and Mission Atlas, remains visible in the header at every width.
- Result completion names the evaluated sites and stored epochs, identifies unchanged-input reruns and explicitly leaves playback paused. New locations receive a site camera fit after a completed request; the first study retains the global view.
- Hollow labeled rings identify evaluated sites, solid dots identify catalog context, and both use the same documented 10 km display lift. This makes points legible without changing the scientific positions or claiming terrain registration. Inspecting an unchecked context site offers an explicit include-and-run action; it never silently changes the study.
- Motion is limited to requested playback, camera transitions and immediate control feedback. Reduced motion retains static controls and pauses remain explicit.
- Native controls, visible labels, keyboard focus, scrolling source disclosures and separate mobile/tablet layouts are functional requirements.

No new logo, photograph, icon library or visual asset is introduced. Published catalog positions, native spacecraft histories and existing Moon tiles supply the product's visual content. The delivery archive is removed from public navigation; routing removal is handled separately.

Geometry and Data delivery share one mounted Moon. Delivery uses a declared task form, a visible last-byte outcome with solver/fidelity/replay labels, and exact transmission, occupancy, storage, battery and buffer records. Transfer and wait controls select Python timestamps. The Earth network camera fits the supplied endpoints at their actual distances; the Moon becomes small at that scale. Geometry catalog markers are hidden while delivery is active and restored when returning to Geometry. Synthetic relay, assumed rates and educational station service remain visible in the network inspector. Browser cancellation stops waiting; it does not claim durable server cancellation.

Delivery rejects unsupported geometry-site copies before changing the task or invalidating exports. A supported south-pole study point can be restored with an explicit top action that changes only lander inputs. Payload, dates, hardware, network and numerical options stay intact. Blocking validation reasons sit beside Plan delivery, and the empty result explains that camera controls change views while Plan delivery starts the Python calculation. A supported study point is not a certified landing site.
