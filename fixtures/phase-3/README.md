# Synthetic Phase 3 environment captures

These JSON files are generated by Python through `npm --prefix web run
sync:science`. They are algorithm/display fixtures, not delivery results.

Their scenarios, finite hardware, service calendars and assumed net rates come
from the original `synthetic-direct` and `synthetic-relay` examples. The sky
directions and uniform skylines are invented: Sun elevation rises from -0.4 to
0.8 degrees over the supplied horizon; the panel skyline is 0.2 degrees and the
antenna skyline is 0 degrees. These inputs are not ephemerides or measured DEMs.
The differing height skylines are explicit test inputs, not a prediction of how
raising equipment changes any real site.

Python computes disk visibility, fixed-panel generation, and base-only battery
replay under an explicit left-sample constant-power assumption. It constructs
contacts only under the independently declared synthetic interval-wide geometry
assumption and original endpoint service. Additional blocked and unknown
candidates prove those cases remain separate from usable contacts. Light time
is disabled only for these synthetic arithmetic examples; it is not physically
zero. No transmission is selected, no radio energy is incurred in the base-only
trace, and no last-byte arrival or delivery feasibility is claimed.

The recorded real LOLA example is kept separately under
`soma/docs/phase-3/environment-real.json`; its unknown measured horizons remain
unknown power. Provenance, methods and checksums are documented in
`soma/docs/phase-3/README.md` and `data/phase3-evidence.manifest.json`.
