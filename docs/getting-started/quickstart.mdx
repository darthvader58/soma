---
title: Your first delivery plan
description: Calculate, replay and export the installed synthetic 100 MiB example without downloading lunar data.
---

Install `soma-lunar[planning]` using the [installation guide](/getting-started/installation). This example runs from any working directory. It uses synthetic contacts, hardware and service assumptions, with assumed net radio rates. It is a software test, not a prediction for a lunar site.

## Load and calculate

```python
from soma.engine import plan_run
from soma.validation import load_scenario, resource_directory

fixture = resource_directory("fixtures") / "synthetic-relay" / "scenario.json"
scenario = load_scenario(fixture)
run = plan_run(scenario, options={
    "chunk_bytes": 104_857_600, "bin_s": 5, "time_limit_s": 30,
})
result = run["result"]

print(result["status"])
print(result["solver_status"])
print(result["model_fidelity"])
print(result["delivered_bytes"])
print(result["final_byte_arrival_utc"])

assert result["status"] == "feasible_under_assumptions"
assert result["model_fidelity"] == "assumed_rate_simulation"
assert result["delivered_bytes"] == 104_857_600
assert run["validation"]["passed"] is True
```

The file contains **100 MiB**, or 104,857,600 bytes and 838,860,800 bits. The fixture's direct contact from 08:50 to 09:10 UTC at 256,000 net bits/s carries only 307,200,000 bits. It cannot finish the file. A 2,000,000 bit/s relay hop needs 419.4304 seconds; the later 10,000,000 bit/s ground hop needs 83.88608 seconds before additional modeled delays and scheduling padding.

This first example uses one whole-file chunk to keep the bounded optimization small. Five-second bins still introduce conservative timing, which remains recorded in the result. Smaller chunks allow more allocation choices and require more solver work; a time limit without a valid incumbent returns `unknown`.

The relay stores the data between its two contacts. The solver also checks finite buffers, both endpoints' radios, electrical demand and the deadline. Actual allocations depend on the discretized model and solver outcome, so use the returned final-byte timestamp rather than hard-coding an expected finish time.

`soma.plan_delivery(scenario)` returns just the native result. `plan_run` retains the analysis inputs, independent replay report and run details needed for audit and export. Read all three of `status`, `solver_status` and `model_fidelity`: they answer different questions. A time-limited feasible incumbent has unproved optimality.

## Replay the selected allocations

```python
from soma.schedule import replay_schedule

report = replay_schedule(
    run["scenario"],
    result["contacts"],
    result["allocations"],
    run["analysis_inputs"]["generation_bins"],
)
assert report["passed"] is True
assert report["delivered_bytes"] == 104_857_600
```

Replay recomputes byte conservation, capacity, causality, storage, service, terminal occupancy, energy and final-byte arrival. Schema validation alone cannot establish those properties.

## Save the run

```python
from pathlib import Path
from soma.exports import create_run_package, json_bytes, summary

Path("synthetic-relay.zip").write_bytes(create_run_package(run))
Path("run.json").write_bytes(json_bytes(run))
Path("scenario.json").write_bytes(json_bytes(scenario))
print(summary(run)["route_family"])
```

The ZIP includes the exact scenario, native result, structured explanation, contacts and schedule CSVs, resource histories, display data and checksummed manifest. It records source-transmit windows, receiver occupancy and byte availability separately. Unknown quantities remain distinct from zero.

## Use the CLI with the saved scenario

Run these commands after the Python example has written `scenario.json`:

```bash
python -m soma validate scenario.json
python -m soma run scenario.json --output-dir soma-relay-run --chunk-bytes 104857600 --bin-s 5 --time-limit-s 30
python -m soma replay soma-relay-run/run.json
python -m soma.verification.exports soma-relay-run/run.zip
```

`plan` prints a native result; `run` also writes a complete export directory and ZIP. A successful CLI execution means the command completed, so inspect the scientific status in the output. A valid infeasible or unknown result is still a completed calculation.
