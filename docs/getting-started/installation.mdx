SOMA's distribution name is `soma-lunar`; its Python import is `soma`. Version 0.1.0 requires **Python 3.12 or newer**. A browser, Cesium account and cloned repository are unnecessary for the library quickstart.

## Install from PyPI

Create an isolated environment, then install the planning workflow:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install "soma-lunar[planning]==0.1.0"
```

On Windows PowerShell, activate the environment with `.venv\Scripts\Activate.ps1`.

Version [0.1.0 is published on PyPI](https://pypi.org/project/soma-lunar/0.1.0/). The release workflow verifies the built distributions before uploading them through GitHub Trusted Publishing. Source installation remains available below for development.

## Choose dependencies

| Installation | What it provides |
| --- | --- |
| `soma-lunar` | Scenario/schema validation, strict JSON and canonical hashing. Does not include the numerical planner dependencies. |
| `soma-lunar[analysis]` | NumPy, SpiceyPy, Rasterio and PyProj for numerical geometry, terrain, illumination and power. |
| `soma-lunar[planning]` | The analysis stack plus PuLP for delivery planning and replay. The current planner imports the analysis dependencies even for synthetic inputs. |
| `soma-lunar[service]` | FastAPI and Uvicorn. Combine with `planning` to serve delivery jobs. |
| `soma-lunar[verification]` | Skyfield for independent ephemeris comparisons; combine with `analysis` or `planning`. |
| `soma-lunar[test]` | Pytest and HTTP test support for a source checkout. |

For a local service with independent geometry verification:

```bash
python -m pip install "soma-lunar[planning,service,verification]==0.1.0"
```

## Dependency versions in 0.1.0

Pip installs the dependencies declared by each selected extra. You do not need to install these packages individually.

| Workflow | Direct dependencies |
| --- | --- |
| Core, always installed | `jsonschema==4.26.0`, `referencing==0.37.0`, `rfc8785==0.1.4` |
| `analysis` | `numpy==2.5.4`, `spiceypy==8.4.0`, `rasterio==1.5.2`, `pyproj==3.8.0` |
| `planning` | All analysis dependencies plus `pulp==3.3.2` |
| `service` | `fastapi==0.163.0`, `uvicorn==0.54.0`; select `planning,service` together for delivery jobs |
| `verification` | `skyfield==1.55`; also select the analysis or planning extra for numerical workflows |
| `test`, for development | `pytest>=8,<10`, `httpx==0.28.1` |

NumPy, Rasterio, PyProj and SpiceyPy contain or use native numerical libraries. Supported wheels normally provide these components. A platform without a compatible wheel can require upstream build tools and native libraries; use each dependency's installation instructions rather than assuming every platform has the same prerequisites. CBC must be executable for scheduling; the check below verifies the solver available through PuLP.

Use `python -m pip check` to detect missing or conflicting installed dependencies. Node.js is needed only for a source checkout's web application or Mintlify tooling; it is not needed to import or run the Python library.

Scientific kernels and rasters are separate from Python dependencies. Installation does not start a scientific-data download. Small manifests, schemas and synthetic fixtures are included as installed resources. See [frames and datasets](/science/frames-data) before acquiring physical inputs.

## Verify the environment

```bash
python -c "import soma; print(soma.__version__)"
python -m soma --help
python -c "import pulp; print(pulp.PULP_CBC_CMD().available())"
```

The last command should print a path to an executable CBC solver. An empty/false value means PuLP cannot find its configured CBC executable. Installation and solver availability depend on the platform; a missing solver is not a scientific infeasibility result. See [troubleshooting](/getting-started/troubleshooting).

The `soma` console command and `python -m soma` expose the same CLI. Continue with [your first synthetic plan](/getting-started/quickstart), which locates its example through installed resources.

## Install from a checkout

Use this route for development, unreleased changes and repository reproduction scripts:

```bash
git clone https://github.com/darthvader58/soma.git
cd soma
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[planning,service,verification,test]"
python -m pytest tests/engine -q
```

Pin a release tag or commit when reproducing a calculation. Keep the scenario, source hashes, solver settings and exported manifest alongside the library version. The [contribution guide](/project/contributing) describes checks for source changes.
